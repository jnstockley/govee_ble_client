# Offline Testing

The pytest suite runs without a Bluetooth adapter, device, API key, or Govee
account. It never scans, connects, pairs, or transmits GATT data. Tests of
command methods record the generated bytes in fake connections. Encryption
tests use an in-memory peripheral with synthetic keys and notifications.

## Running Locally and in CI

Install the locked development environment and run from the repository root:

```sh
uv sync --locked --all-groups
uv run pytest
uv run pytest --cov=govee_ble_client --cov-branch --cov-report=term-missing
```

Pytest's `testpaths` selects `tests/`, and `norecursedirs` excludes directories
named `examples`. Example-script tests are retained in `tests/examples/` but
are excluded from default pytest runs and JUnit reports. Library tests remain
in `tests/`. The configured Python paths make the source package importable
without environment-variable setup. Async tests use `asyncio.run`, so no additional async pytest plugin is
required.

The existing CI test command is supported by the locked `pytest-cov` dependency:

```sh
uv run pytest --cov=govee_ble_client --cov-branch --cov-report=xml --junitxml=junit.xml -o junit_family=legacy
```

Coverage measures only `govee_ble_client` and explicitly omits `examples/`
from collection and reports. Coverage checks require at least 95% for the
library, including branches.
Coverage artifacts contain local source paths and statistics, not BLE captures.

## Bluetooth Is Blocked by Default

`tests/conftest.py` installs a guard before test-module collection and restores
it between tests. Attempts to construct a real Bleak client or scanner, start
discovery, connect, read, write, or subscribe fail the test immediately. Tests
replace those entry points with explicit fakes or `AsyncMock` objects where
needed. A missing mock therefore fails instead of reaching the host adapter.

The excluded example tests exercise helper functions and script entry points
with mocked discovery and fake connections. Private `.pklg` files and locally
generated investigation reports are not required.

## Coverage Map

| Area | Offline checks |
| --- | --- |
| Discovery | Advertisement copying and name fallback; name/service/manufacturer/predicate filters; UUID case handling; RSSI ordering; scan timeout validation |
| GATT transport | Connected/disconnected guards; argument forwarding; immutable write data; context cleanup; connection errors; replacement of stale clients |
| Common framing | Recorded query/control frames; padding and XOR; payload bounds; malformed replies; unknown values |
| V1 encryption | AES and RC4 known vectors; fresh RC4 tails; synthetic handshake; noise and timeout handling; public/session key decoding; cleanup and notification failures |
| H5179 | Temperature/humidity/battery queries; signed temperature and unit conversion; sensor bounds; missing and unknown replies; GATT validation |
| H7126 | Every query and control method, including filter reset; mode family versus selected mode; display/power/filter replies; three-segment schedules; Continuous and invalid input |
| H7102 | Every query and control method; modes and speeds 1–8 encoding; per-segment oscillation; Custom blocks; live oscillation versus acknowledgements; partial state updates; session and reconnect failures |

Tests include both finite duration boundaries and the reserved `FFFF FFFF`
Continuous sentinel. A numeric duration of 65535 minutes is rejected because
it would otherwise encode the same bytes as Continuous; use `None` instead.

## Adding a Test

Add `test_*.py` modules under `tests/`. For a profile operation, check the exact
command against a recorded or independently specified frame using a fake
connection. Verify invalid input produces no recorded write. For replies,
check raw-byte preservation, decoded values, malformed input, and unknown fields.
For stateful code, test timeouts, partial updates, and cleanup after failure.

Offline tests verify encoding and software behavior. Speeds, modes, and
firmware variants listed as unverified in [project status](PROJECT_STATUS.md)
still need a deliberate hardware comparison before their status changes.
